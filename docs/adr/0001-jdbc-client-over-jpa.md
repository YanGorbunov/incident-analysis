# ADR-0001. JdbcClient и SQL вместо JPA

**Статус:** принято

## Контекст
Модель — полтора десятка таблиц, CRUD простой. Основная ценность компонента — аналитика:
агрегаты с `FILTER`, `percentile_cont`, полнотекстовый поиск, разрезы по связям многие-ко-многим.

## Решение
Доступ к данным — `JdbcClient` (Spring 6.1+) и явный SQL. Строки маппятся в record'ы
(`DataClassRowMapper`), динамические условия собираются из фрагментов только с именованными
параметрами (`IncidentSql`).

## Последствия
- `+` Запросы видны целиком, их можно проверить в psql и `EXPLAIN`.
- `+` Нет N+1, ленивой загрузки и неожиданных flush.
- `−` Больше шаблонного кода в CRUD; оптимистичная блокировка написана руками (`WHERE version = :v`).
- `−` Нюанс: `JdbcClient.paramSource(obj)` заменяет параметры, заданные через `param()`,
  поэтому record'ы превращаются в `MapSqlParameterSource` (`SqlParams.of`).
