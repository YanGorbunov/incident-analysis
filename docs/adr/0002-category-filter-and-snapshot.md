# ADR-0002. Категория = фильтр + зафиксированный срез

**Статус:** принято

## Контекст
В ВКР аналитик выделяет категорию, задавая параметры фильтрации (Рис. 3.12), а отчёт строится
по категории. В физической модели осталось только `category(id, name, creation_date_time)` и связь
`incident_has_category` — правило, по которому выделена категория, не сохранялось.

## Варианты
1. **Только фильтр** (динамическая категория). Отчёт всегда актуален, но меняется задним числом:
   переоткрыли инцидент — изменился отчёт, уже отправленный руководителю.
2. **Только снимок.** Воспроизводимо, но непонятно, как категория получена, и её нельзя пересчитать.
3. **Фильтр + снимок.**

## Решение
Вариант 3. `category.criteria JSONB` хранит фильтр (тот же объект `IncidentCriteria`, что
и у поиска), `category_incident` — срез на момент `snapshot_at`. Отчёт строится по срезу.
Пересчёт — явное действие «Обновить срез».

## Последствия
- `+` Отчёт воспроизводим, а правило выделения прозрачно.
- `+` Один объект критериев для списка, категории и отчёта — одна реализация SQL.
- `−` Аналитик должен помнить об обновлении среза; в списке категорий показана его дата.
