# ADR-0005. Резервное копирование — задача инфраструктуры

**Статус:** принято

## Контекст
На структурной схеме ВКР (Рис. 3.3) есть «модуль резервного копирования» внутри сервера приложения.

## Решение
Приложение резервным копированием не занимается. В `docker-compose.yml` — сервис с `pg_dump`
по расписанию и ротацией (7 дней / 4 недели / 6 месяцев), `scripts/restore.sh` — восстановление.
В промышленной эксплуатации — средства организации (pgBackRest/WAL-архив, СХД).

## Почему
- Копия, которую делает само приложение, ломается вместе с ним.
- Консистентный дамп и point-in-time recovery — возможности СУБД, а не Java-кода.
- Права на запись в хранилище копий не должны быть у веб-приложения.
