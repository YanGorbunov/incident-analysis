# ADR-0004. Коды объектов — бизнес-атрибуты, а не первичные ключи

**Статус:** принято

## Контекст
Табл. 2.3 ВКР задаёт коды вида `ГГММДД.XXXX`, `ВВВ.XXXX`, `ДДДД.XXXX` как «формулы
идентификатора», при этом ключи в физической модели — `BIGINT`. Код с точкой в BIGINT не
помещается, а код, зависящий от изменяемых атрибутов (ведомство КЕ, должность сотрудника),
не может быть ключом.

## Решение
- Первичный ключ — суррогатный `BIGINT GENERATED ALWAYS AS IDENTITY`.
- Код — отдельная колонка `code UNIQUE` с CHECK по формату, присваивается при создании
  и **не меняется** (КЕ переехала в другое ведомство — код прежний, иначе ломаются внешние ссылки
  и документы).
- Номер внутри префикса выдаёт атомарный upsert в `code_counter`
  (`INSERT … ON CONFLICT DO UPDATE … RETURNING`) — без гонок при параллельном импорте.
- Код инцидента — `ГГММДД` (как назван в ВКР), а не `ДДММГГ` (как нарисован): так коды
  сортируются хронологически. Дата берётся в часовом поясе `app.zone`.

## Последствия
- `+` Коды из ВКР сохранены и человекочитаемы, ключи — стабильны.
- `−` Код может «устареть» относительно текущего ведомства/должности — это осознанно.
