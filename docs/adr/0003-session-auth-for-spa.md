# ADR-0003. Сессия и CSRF-cookie вместо JWT

**Статус:** принято

## Контекст
SPA и API отдаются одним приложением с одного origin. Пользователей — единицы, сервер — один.

## Решение
Серверная сессия (cookie `HttpOnly`, `SameSite=Lax`), CSRF-токен в cookie `XSRF-TOKEN`,
который фронтенд возвращает в заголовке `X-XSRF-TOKEN` (`csrf.spa()` в Spring Security).
Вход — JSON-эндпоинт с двумя шагами: пароль, затем TOTP-код, если второй фактор включён.
При входе меняется идентификатор сессии (защита от фиксации).

## Последствия
- `+` Выход инвалидирует сессию на сервере; токена, который живёт до истечения срока, нет.
- `−` Отключение пользователя администратором действует со следующего входа — уже открытая
  сессия живёт до таймаута (8 ч). Для мгновенного отзыва нужен `SessionRegistry`; пока не сделано.
- `+` Токен не лежит в `localStorage`, где его может прочитать XSS.
- `−` Горизонтальное масштабирование потребует Spring Session (Redis/JDBC) — сейчас не нужно.
